# Intelligence Evidence Compaction Phase 4 Checkpoint

Date: 2026-07-09

## Scope

Phase 4 implements a disabled-by-default evidence compaction layer after tool execution and before tool results enter model-visible context. It does not start retry/fallback hardening, provider routing changes, MCP startup changes, service changes, schedules, credentials, approval-gate changes, or production deployment.

New flag/config:

- `agent.intelligence_evidence_compaction_enabled`
- `HERMES_INTELLIGENCE_EVIDENCE_COMPACTION=1`
- `agent.intelligence_evidence_max_compacted_bytes`
- `agent.intelligence_evidence_max_retained_error_lines`
- `agent.intelligence_evidence_max_retained_log_lines`
- `agent.intelligence_evidence_raw_output_spill_dir`
- `agent.intelligence_evidence_redact_secrets_before_spill`
- `agent.intelligence_evidence_enable_raw_output_references`
- `agent.intelligence_evidence_fallback_to_raw_on_compaction_failure`

Safe default: with the flag off, tool results are unchanged.

## Code Diff Summary

- Added evidence compaction config/env flag handling in `agent/intelligence_policy.py`.
- Added tool-result classification for logs, errors, JSON, web, connector, file, and text outputs.
- Added structured compact evidence output with `key_findings`, `preserved_evidence`, `omitted`, size metadata, and optional raw reference.

- Added optional local raw-output spill with `0600` file permissions under a configurable directory or `$HERMES_HOME/evidence_spills`.

- Wired compaction into both sequential and concurrent tool-result paths in `agent/tool_executor.py`.
- Extended reports and `hermes intelligence-policy` output with compaction counters and savings.
- Added Phase 4 five-mode benchmark.

## Compacted Evidence Examples

- Logs: repeated heartbeat lines are deduplicated; timestamped `ERROR`, status, path, and line references are preserved.
- Error trace: traceback header, `File "...", line N`, and exception message are preserved.
- JSON payload: `id`, `status`, `timestamp`, URL/source, and error fields are preserved.
- Web/article: title, source URL, date, claim, and citation fields are preserved.
- File/repo: paths, line references, relevant snippets, and errors are preserved.
- Connector-style email/calendar/task payloads: IDs, sender/subject/date/status are preserved while raw body-like content is omitted from reports.

## Redaction And Spill

- Secret patterns such as `api_key=...`, bearer tokens, and `sk-...` keys are redacted before compacted output and before spill.
- Raw-output references are disabled by default.
- The focused spill test enables raw refs, verifies a local file is created, and verifies the secret is absent from spilled content.
- The benchmark uses no raw spill refs, so `raw_spill_count=0`.

## Known Limitations

- The benchmark is fixture-derived; provider responses and connector data are not live.
- Compaction is rule-based and conservative. It preserves high-signal evidence but does not yet perform semantic summarization.
- Raw refs are local filesystem paths and are not exposed to users by the report unless explicitly surfaced later.
- Multimodal tool outputs are left unchanged in this phase.
- No retry/fallback hardening, provider routing, MCP startup changes, or production deployment are included.
