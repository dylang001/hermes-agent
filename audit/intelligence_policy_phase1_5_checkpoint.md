# Intelligence Policy Phase 1.5 Checkpoint

Date: 2026-07-09

## Scope

Phase 1.5 adds measurement calibration only. It does not add Phase 2 memory gating, tool-schema reduction, MCP routing, retry changes, provider fallback changes, production deployment, service restarts, credential changes, schedule changes, or approval-gate changes.

The observer remains disabled by default. It is enabled only by `HERMES_INTELLIGENCE_POLICY=1` or `agent.intelligence_policy_enabled: true`.

## Code Diff Summary

- Added `agent/intelligence_policy.py` with deterministic request/error classifiers, non-enforced tool-budget metadata, a passive per-turn observer, sanitized report writer, and real-runtime request-size capture.
- Hooked the observer into `AIAgent` initialization, turn-context completion, request-payload assembly, tool execution counters, API error classification, and turn finalization.
- Added read-only CLI display through `hermes intelligence-policy [--json]`.
- Retained the 20-case benchmark as `fixture_policy_contract_test`, explicitly not a token or latency baseline.
- Added a mocked real-runtime sample collector that runs `AIAgent.run_conversation` through normal prompt construction, tool registration, memory prefetch, request assembly, and turn finalization with local fixture memory and mocked provider responses.

## Classifier Calibration

Tested expectations include:

- long external article/PDF summary with citations -> `analysis_or_research`
- current competitor research -> `analysis_or_research`
- current vendor pricing/feature comparison -> `analysis_or_research`
- current vendor pricing from one source -> `scoped_lookup`
- calendar availability lookup -> `scoped_lookup`
- inbox summary -> `scoped_lookup`
- daily priorities across inbox/calendar/tasks -> `analysis_or_research`
- code patch after approval -> `execution_task`
- provider quota/auth investigation -> `analysis_or_research`
- generic factual question with no tools -> `direct_answer`

Provider quota/auth investigation is classified as `analysis_or_research` because Phase 1.5 is still observational: the correct behaviour is to inspect logs/config and recommend the safe fallback action, not execute fallback changes.

## Known Observability Gaps

- Runtime sample provider outputs are mocked, so reported tool calls are zero and provider token counters remain whatever the local mocked turn reports.
- The sample suite validates active local prompt/schema/request sizing, not live connector or web-source quality.
- Memory measurements use sanitized fixture memory in the sample collector. They prove the prefetch path is measured, not that private live memory retrieval is optimal.
- The report stores numeric sizes and source categories only; it intentionally does not store raw request payloads, raw memory, raw email bodies, credentials, or full tool outputs.
