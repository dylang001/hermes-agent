# Intelligence Tool Policy Phase 3 Checkpoint

Date: 2026-07-09

## Scope

Phase 3 implements lazy request-aware tool schema exposure behind a new disabled-by-default flag. It does not start Phase 4 evidence compaction, retry/fallback changes, provider routing changes, production deployment, service changes, schedules, credentials, or approval-gate changes.

New flag/config:

- `agent.intelligence_tool_policy_enabled`
- `HERMES_INTELLIGENCE_TOOL_POLICY=1`
- `agent.intelligence_tool_policy_max_exposed_tools_per_group`
- `agent.intelligence_tool_policy_always_include`
- `agent.intelligence_tool_policy_exclude_write_tools_unless_approved`
- `agent.intelligence_tool_policy_fallback_to_full_on_tool_miss`

Safe default: with the flag off, `api_kwargs["tools"]` is unchanged.

## Code Diff Summary

- Added tool policy config parsing and env flag handling in `agent/intelligence_policy.py`.
- Added tool exposure groups: `none`, `minimal_readonly`, `research`, `workspace_readonly`, `personal_readonly`, `engineering_readonly`, `engineering_execution`, and `full_current_default`.
- Applied the policy only at request-build time after LLM request middleware, by filtering `api_kwargs["tools"]`.
- Preserved `agent.tools` and existing direct tool execution paths.
- Added conservative fallback to `full_current_default` for unknown/ambiguous connector/tool requests and missing required groups.
- Extended policy reports with tool group, before/after tool counts, schema bytes before/after, token savings, omitted categories, fallback reason, write-tool exclusion, and MCP startup marker.
- Extended the read-only `hermes intelligence-policy` output.
- Added Phase 3 four-mode benchmark and updated mocked runtime samples.

## MCP Startup Proof

The tool policy routes only over the already-present `api_kwargs["tools"]` list. It does not import MCP modules, call MCP discovery, refresh MCP tools, or start MCP servers. Reports mark `mcp_started_during_request_preparation=false`; benchmark summary reports `mcp_startup_regressions=0`.

## Known Limitations

- Phase 3 filters model-visible schemas only; it does not permanently remove tools or alter tool execution.
- The benchmark is fixture-derived and the personal connector schemas are mocked for dry-run validation.
- The policy is deterministic keyword/category based and conservative. Unknown or ambiguous tool requests fall back to full exposure.
- If a needed tool group is absent from the active local tool list, policy falls back to full exposure.
- No evidence compaction, MCP lazy startup changes, retry/fallback hardening, or provider routing changes are included.
