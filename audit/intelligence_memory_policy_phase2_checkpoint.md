# Intelligence Memory Policy Phase 2 Checkpoint

Date: 2026-07-09

## Scope

Phase 2 implements request-aware memory gating behind a new disabled-by-default flag. It does not start Phase 3 tool-schema reduction, MCP routing, evidence compaction, retry/fallback changes, provider routing changes, service changes, production deployment, schedules, credentials, or approval-gate changes.

New flags/config:

- `agent.intelligence_memory_policy_enabled`
- `HERMES_INTELLIGENCE_MEMORY_POLICY=1`
- `agent.intelligence_memory_token_budget`
- `agent.intelligence_memory_max_entries`

Safe default: when the memory policy flag is off, prefetched memory is returned unchanged.

## Code Diff Summary

- Added memory policy config parsing and env flag handling in `agent/intelligence_policy.py`.
- Added deterministic memory decisions: `skipped`, `light`, `project`, `user`, `full`.
- Applied policy only to external prefetched volatile memory in `agent/turn_context.py`, after `prefetch_all()` and before user-message injection.
- Extended reports with memory policy enabled/disabled, decision, entries before/after, tokens before/after, estimated savings, source categories, reason code, token budget, and max entries.
- Extended `hermes intelligence-policy` read-only CLI output with Phase 2 memory fields.
- Added focused tests and a 20-case three-mode Phase 2 benchmark.

## Example Memory Decisions

- Generic factual question: `skipped`, reason `generic_direct_answer`.
- Current competitor/vendor research: `skipped`, reason `external_current_research`.
- Vendor recommendation with explicit user budget/preferences: `user`, reason `user_constraints_relevant`.
- Hermes logs/runtime diagnosis: `project`, reason `project_research_constraints`.
- Inbox/calendar/task lookup: `user`, reason `personal_lookup`.
- Prior decision/document lookup: `project`, reason `project_or_prior_lookup`.
- Sensitive/private memory request: `skipped`, reason `sensitive_or_private_memory_risk`.

## Known Limitations

- Phase 2 gates only external prefetched volatile memory. It does not reduce system prompt size, tool schema size, MCP exposure, provider routing, retries, or fallback behaviour.
- The 20-case benchmark is fixture-derived and validates policy behavior, not live connector quality.
- Runtime samples use mocked provider responses, so tool calls are zero and provider token counters are not live-performance data.
- Memory relevance is deterministic keyword/rule based. It is conservative and intentionally avoids semantic retrieval changes until reviewed.
- Reports store only counts, source categories, decisions, reason codes, and size estimates. They do not store raw memory content.
